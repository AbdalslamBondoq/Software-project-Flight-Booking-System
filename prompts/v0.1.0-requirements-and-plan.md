## Goal

Understand the assigned case study (Group 17: Flight Booking System), then write the project description, the functional and non-functional requirements, and the case-specific incremental development plan.

## Key instructions sent to the agent

- "Explain exactly what is required," together with the project instructions file and our case study number (17).
- "The description feels the same as the requirements; it keeps repeating them. Let's rewrite both and get them right."
- The team's own decisions were given to the agent to use: 50% refund up to 14 days before departure, and a 10-minute seat hold.

## Intended outputs

- A short project description that does not repeat the requirements.
- Numbered functional and non-functional requirements.
- An incremental plan that follows the format in the instructions.

## Acceptance criteria

- The description covers only the purpose, users, main challenge and scope.
- Every requirement has an ID and can be traced to the plan.
- Each increment in the plan has a goal, tools and acceptance criteria.

## Corrections made by the team

- The first description repeated the requirements as a feature list; it was rewritten.
- The first plan lacked the main question, tools and acceptance criteria per increment; these were added after checking the instructions.
- The agent's own refund assumption was replaced by the team's decision.
